# Переплёт — локальная платформа викторин

Работает на ноутбуке с XAMPP; участники подключаются по локальной сети. Интернет, облако, Node.js, Composer и MySQL для работы не нужны. PHP 8.1+, SQLite, JavaScript без сборки. Интерфейс на русском, адаптирован для телефонов.

## Обновление существующей установки

Для обновления поверх используйте **`quiz-library-update.zip`**, инструкция — `UPDATE-WINDOWS.txt`. Он содержит только код и документацию, без `data` и `uploads`. Остановите Apache, сделайте резервную копию всей рабочей папки, объедините папки с заменой файлов, затем запустите Apache и обновите браузеры через Ctrl+F5. Повторно задавать пароль не нужно. Новая таблица `run_control` создаётся автоматически, существующие данные сохраняются.

## Рекомендуемая версия

Для новой установки используйте **XAMPP for Windows 8.5.12, 64 bit (PHP 8.5.12)** с [официального сайта Apache Friends](https://www.apachefriends.org/download.html). Номер относится к сборке с PHP, а не к версии окна XAMPP Control Panel. Для запуска достаточно Apache; MariaDB/MySQL, FileZilla, Mercury и Tomcat не нужны. Требуются PHP 8.1+ и расширения `pdo_sqlite`, `mbstring`, `fileinfo`. Код проверялся на PHP 8.5.4; отдельная проверка Windows/XAMPP на ноутбуке выполняется при установке.

## Что включено в архив переноса

В архиве `quiz-library-xampp.zip` находятся код платформы, **две сохранённые викторины**, текущее оформление общих страниц и загруженные изображения. База в архиве подготовлена отдельно: команды, ответы, история запусков, попытки входа, сеансы и пароль ведущего удалены. Рабочая база в контейнере не менялась. После установки задайте новый пароль и запустите нужную викторину. Текущая игра автоматически не продолжается.

## Установка на Windows / XAMPP

1. Полностью распакуйте ZIP (не запускайте файлы внутри окна архива). Скопируйте папку `quiz-library` в `C:\xampp\htdocs\quiz-library`.
2. В XAMPP откройте Apache → Config → PHP (php.ini). Убедитесь, что включены строки (без `;` в начале):
   ```ini
   extension=pdo_sqlite
   extension=mbstring
   extension=fileinfo
   ```
   Для больших видео при необходимости установите:
   ```ini
   upload_max_filesize=64M
   post_max_size=70M
   ```
   Приложение принимает один файл до 64 МБ. PHP может ограничивать загрузку сильнее.
3. Запустите Apache. Папки `data` и `uploads` должны быть доступны ему для записи. В стандартной установке XAMPP это обычно уже так.
4. Запустите `setup-windows.cmd` двойным щелчком — он проверит версию PHP, расширения и папки для записи, затем предложит задать пароль (ищет PHP в стандартном XAMPP). Либо откройте командную строку Windows и выполните:
   ```bat
   cd /d C:\xampp\htdocs\quiz-library
   C:\xampp\php\php.exe server\setup.php
   ```
   Введите собственный пароль ведущего длиной минимум 12 символов и не более 72 байт UTF-8 (например, до 72 латинских или 36 русских букв). Универсального пароля нет. Настройка доступна только через командную строку ноутбука. Этой же командой можно сбросить забытый пароль, не удаляя данные. Если база пустая, при первой настройке добавляется демонстрационная викторина «Между строк». В архиве переноса викторины уже есть, они сохранятся.
5. Откройте `http://localhost/quiz-library/`, выберите «Я ведущий», введите пароль.
6. Узнайте IPv4 ноутбука командой `ipconfig`, например `192.168.1.20`. Участники открывают `http://192.168.1.20/quiz-library/` на телефонах.

Все устройства подключаются к одной Wi-Fi сети. В настройках сети не должно быть изоляции клиентов / гостевого режима. Разрешите Apache в брандмауэре Windows для частной сети. Если Apache использует порт 8080, ссылка имеет вид `http://192.168.1.20:8080/quiz-library/`. IP может меняться после переподключения к Wi-Fi.

Доступ к `data` закрыт через `.htaccess`. В стандартном XAMPP/Apache `AllowOverride` должен разрешать эти правила. Перед первым мероприятием проверьте: адрес `http://localhost/quiz-library/data/library.sqlite` должен возвращать 403, а не скачивать базу. Файлы `server` и `tests` также закрыты от HTTP. Не используйте для реального мероприятия голый `php -S` без приложенного `server/dev-router.php`: встроенный сервер игнорирует `.htaccess`.

## Как провести игру

1. **Мои викторины → Создать викторину.** Введите название и описание. Добавьте вопросы, правильные ответы и баллы. Сохраните.
2. В блоке **«Проведение викторины»** можно выбрать показ результатов именно для этой викторины: по общей настройке, показывать или не показывать баллы и правильные ответы. Также можно включить **«Ведущий открывает слайды по кнопке»**: при запуске закрыты все слайды, ведущий открывает их последовательно из монитора. Эти настройки применяются при следующем запуске. Уже открытые слайды доступны командам по порядку, автоматического принудительного перевода отставших команд нет.
3. Типы заданий: один ответ, несколько ответов, текст, число с погрешностью, несколько текстовых полей, информационный слайд и ссылка на материал. Текст у информационного слайда необязателен: можно оставить только медиа или оформление. При нескольких вариантах баллы начисляются за полностью верный набор, без частичных баллов.
4. К вопросу можно загрузить изображение/GIF, видео или аудио. Поддерживаются JPG, PNG, GIF, WebP, MP4, WebM, MP3, OGG, WAV. Для локальной работы используйте загруженные файлы; внешним HTTPS-ссылкам нужен интернет. Ссылки должны вести на сам медиафайл, страницы YouTube и iframe не поддерживаются. Для совместимости телефонов удобны JPEG/PNG, MP4 (H.264/AAC), MP3.
5. **Оформление** открывает отдельный редактор всей страницы. Слева доступны главная с выбором роли, вход ведущего, создание и восстановление команды, ожидание игры, а также начало, каждый вопрос и результаты выбранной викторины. По центру отображается реальная страница; справа — настройки выделенного блока. Нажмите на блок, чтобы выбрать его, перетащите мышью, измените ширину за угол рамки. Текст можно изменить двойным щелчком или в правой панели; доступны размер, шрифт, цвет, жирность и выравнивание. Изображения и GIF добавляются с компьютера, можно заменить файл, копировать элементы и менять порядок слоёв. Цвет и изображение фона относятся ко всей странице. Есть режимы «Компьютер» / «Телефон», просмотр без выделения, разворачивание редактора и отмена/возврат изменений. Кнопки и поля нельзя удалить или изменить их действие; в предпросмотре они не отправляют данные. Нажмите «Сохранить», затем обновите страницу участника. Сохраняется только оформление: вопросы, правильные ответы и уже полученные баллы не меняются. В активной викторине внешний вид обновляется без повторного запуска.
6. Нажмите ▶ на карточке викторины. Подтвердите запуск нового сеанса. Активной бывает одна игра. Новый запуск завершает прежний сеанс и начинает новый с нуля; история сохраняется. Редактирование викторины после запуска влияет только на следующие сеансы.
7. Участники выбирают «Я участник», задают уникальное название команды и нажимают «Начать приключение». Каждая команда проходит задания в своём темпе.
8. **Монитор игры** открывается в той же вкладке через левое меню. При необходимости его можно открыть отдельно обычными средствами браузера. Обновление каждые 2 секунды, без перезагрузки. Видны черновики выбранных вариантов/введённого текста (после паузы в 0,5 с), отправленные ответы, правильность, баллы, прогресс, наличие связи. Черновики выделены отдельно и не дают баллы. Ответ можно нажать, чтобы проверить его или вручную скорректировать баллы. Таблица сортируется по сумме баллов.
9. В мониторе доступны история последних 50 сеансов и CSV с результатами. История в базе не удаляется. В конструкторе доступен экспорт/импорт викторины JSON. JSON содержит ссылки на загруженные файлы, сами медиа нужно переносить отдельно из `uploads`.
10. Нажмите «Завершить» в коллекции, когда мероприятие закончено. Результаты останутся в истории. В настройках можно закрыть регистрацию, изменить лимит команд и отключить показ правильных ответов после завершения командой всех вопросов.

## Сохранение и проверка ответов

- Отправленные ответы хранятся в SQLite на ноутбуке; прогресс восстанавливается по секретному токену команды, сохранённому в браузере. Обновление/закрытие вкладки не теряет прогресс. Не используйте приватный режим: после его закрытия браузер удаляет локальные данные.
- Выбранный, но не отправленный ответ дополнительно сохраняется на устройстве и отправляется ведущему как черновик. Во время разрыва связи остаётся локальная копия; отправьте ответ после восстановления сети. Не очищайте данные браузера в процессе игры.
- Кнопка «Код команды» показывает секретный код восстановления. С ним можно вернуться с другого устройства или после очистки браузера через «Уже участвовали?». Код даёт доступ к этой команде — храните его внутри команды. Название само по себе не даёт доступа к прогрессу. На новом сеансе команды регистрируются заново.
- До отправки можно менять выбор. Отправленный ответ неизменяем для участника. Повторная отправка после потери сетевого ответа не дублирует и не меняет результат. Сервер требует последовательного прохождения.
- Текст: регистр, пробелы, пунктуация и Е/Ё игнорируются. Можно задать несколько допустимых формулировок. Баллы начисляются за нормализованное точное совпадение. Процент сходства (расстояние Левенштейна по символам Unicode) служит подсказкой ведущему, это не смысловая оценка. Например, близкий по написанию неправильный ответ может иметь высокий процент. Для спорных случаев есть ручная оценка. Синонимы нужно перечислять явно.

## Доступ и безопасность

Пароль хранится только как хеш `password_hash`. Действия ведущего проверяются сервером, в том числе при прямых запросах к API. Есть защита от CSRF, ограничение входа (8 неверных попыток с одного IP за 15 минут), HttpOnly/SameSite cookie, обновление ID сессии при входе, срок сессии 8 часов. Смена пароля завершает другие сеансы ведущего. Правильные ответы и объяснения не передаются незавершившим командам. Медиа проверяются по MIME, исполняемые файлы и SVG не принимаются, загрузки получают случайные имена. Пользовательский HTML/JavaScript не поддерживается.

На общем ноутбуке завершайте сеанс ведущего перед передачей устройства участникам. Не открывайте участникам phpMyAdmin и панель XAMPP. Эта платформа рассчитана на доверенную локальную сеть: обычный HTTP не шифрует трафик. Для недоверенной сети потребуется HTTPS. Доступ к самому ноутбуку, файлам базы и командной строке должен оставаться у организатора; веб-пароль не защищает от владельца файлов.

## Нагрузка и резервные копии

SQLite включён в режиме WAL, ожидание блокировок 8 секунд, записи ответов выполняются короткими транзакциями. Сессионная блокировка PHP освобождается до основных операций. Монитор и участники используют короткие опросы (2 и 4 секунды), без постоянно занятых PHP-процессов и WebSocket-сервера. Нет внешних библиотек и сетевых зависимостей интерфейса.

Автоматическая проверка в контейнере: 40 одновременных команд, у каждой регистрация, черновик, отправка и три чтения прогресса (8 запросов с учётом bootstrap); медиана 1,67 с, максимум 1,75 с на весь сценарий, без ошибок. Это проверка программной логики и конкурентных записей, а не гарантия скорости конкретного ноутбука/Wi-Fi. Перед мероприятием проведите репетицию с устройствами, особенно при видео: одновременная загрузка больших файлов нагружает сеть. Ноутбук не должен засыпать во время игры.

Для полной резервной копии завершите игру, остановите Apache и скопируйте `data` и `uploads` вместе. Остановка нужна для согласованной копии SQLite и файлов WAL/SHM. Восстановление: остановите Apache, верните обе папки из одной копии и запустите Apache. Не размещайте базу SQLite на сетевом диске.

## Разработка и проверки

```sh
php server/setup.php
PHP_CLI_SERVER_WORKERS=6 php -S 127.0.0.1:8093 -t . server/dev-router.php
```

В Windows переменная `PHP_CLI_SERVER_WORKERS` не поддерживается, для мероприятия используйте Apache XAMPP. Встроенный сервер — только для разработки.

Проверки синтаксиса: `php -l api.php`, `php -l server/bootstrap.php`, `php -l server/setup.php`, `node --check assets/app.js`.

`tests/integration.py` меняет данные и настройки — запускайте только на отдельной тестовой копии проекта с отдельной базой. Передайте адрес через `QUIZ_TEST_URL` и путь к файлу тестового пароля через `QUIZ_TEST_PASSWORD_FILE`. Скрипт проверяет права доступа, CSRF, скрытие правильных ответов, черновики, восстановление, проверку всех типов заданий, повторные запросы, замороженные версии игр, CSV, ручную оценку, настройки, конкурентную работу 40 команд, ограничение входа и завершение старых сессий после смены пароля.

Структура: `api.php` — HTTP API, `server/bootstrap.php` — БД/валидация/проверка ответов, `server/setup.php` — настройка из CLI, `assets/app.js` — интерфейс, `assets/style.css` — оформление, `data` — база, `uploads` — медиа.

Документация выбранных механизмов: [PDO SQLite](https://www.php.net/pdo-sqlite), [SQLite WAL](https://www.sqlite.org/wal.html).

Полноэкранный редактор находится в `assets/designer.js` и `assets/designer.css`. Оформление общих страниц хранится в конфигурации SQLite, индивидуальное оформление — в викторине и визуальной части активного сеанса. Предпросмотр использует те же функции отображения, что и участник, в iframe с того же сайта; данные не отправляются во внешние сервисы. Проверки API оформления: `tests/design.py`, только на тестовой копии с теми же переменными окружения, что у интеграционных тестов.

## Защита работы в конструкторе

Ошибка сохранения открывает заметное окно и постоянный список полей с номерами слайдов. Нажмите пункт списка, чтобы перейти к проблемному слайду и полю. Неудачная попытка не меняет сохранённую викторину.

Изменения в конструкторе автоматически записываются в локальный черновик браузера. На странице «Мои викторины» можно восстановить несохранённую работу, в том числе после закрытия браузера. Для этого нужны те же устройство, профиль браузера и адрес сайта; черновик с IP-адреса не появится автоматически на другом домене. Приватный режим, очистка данных браузера или запрет локального хранилища могут удалить или отключить черновики. Если записать черновик невозможно, конструктор покажет предупреждение. После успешного сохранения соответствующий черновик удаляется. Это дополнение к сохранению на сервер, а не замена резервным копиям.

## Информационные слайды и монитор

Информационные слайды не являются ответами: они не входят в итоговый разбор участника и CSV. В мониторе их столбцы скрыты по умолчанию, при необходимости включите флажок «Информационные слайды». Общий прогресс команды продолжает учитывать прохождение всех слайдов.

В режиме ведущего будущие слайды не передаются участникам до открытия. Панель «Показ слайдов ведущим» находится в мониторе. Повторная отправка одного и того же открытия не пропускает следующий слайд. Открытые слайды не закрываются обратно; команды сохраняют ответы и проходят доступную часть по порядку. Если результаты скрыты, после завершения отображается только подтверждение окончания, без оценок и ключей ответов.

## Несколько полей и ссылки

В конструкторе выберите тип «Несколько текстовых полей». На слайде можно разместить от 2 до 12 вопросов: для каждого укажите подпись, допустимые ответы с новой строки и баллы (от 1 до 100). Общий текст слайда необязателен. Баллы за слайд складываются автоматически; верный ответ в одном поле приносит свои баллы даже при ошибке в другом. Пустое отдельное поле оценивается в 0, для отправки нужен хотя бы один непустой ответ. Проверка, как у обычного текстового ответа: без регистра, пробелов, пунктуации и различия Е/Ё. Черновик сохраняет каждое поле.

В мониторе ячейка показывает ответы и баллы каждого поля. Частично верный слайд выделяется жёлтым. Нажмите ячейку, чтобы увидеть допустимые ответы, сходство и изменить баллы отдельно для каждого поля. В итогах участника поля разбираются по отдельности, если показ результатов разрешён. В CSV каждому полю соответствует отдельная строка; «Баллы» — сумма команды, «Баллы за ответ» — оценка этого поля.

Для отдельного материала выберите тип «Ссылка на материал», заполните HTTP/HTTPS-адрес и при желании текст кнопки. Для ссылки внутри обычного вопроса раскройте «Добавить ссылку на материал». Ссылка открывается новой вкладкой и не завершает текущий вопрос. Доступ к внешнему сайту зависит от подключения устройства участника. Слайд-ссылка имеет 0 баллов, не попадает в итоговый разбор и CSV; в мониторе скрывается вместе с информационными слайдами флажком «Информационные слайды и ссылки». Новые типы доступны и в редакторе оформления.

Проверка новых типов: `tests/question-types.py` с `QUIZ_TEST_URL` и `QUIZ_TEST_PASSWORD_FILE`, только на отдельной тестовой установке. Таблица `answer_parts` для оценок отдельных полей создаётся автоматически при обновлении; существующие данные не заменяются.

## Страницы в редакторе оформления и сброс

В разделе «Оформление» доступны главная с выбором роли, вход ведущего, создание и восстановление команды, ожидание игры, приглашение в новую викторину и отдельное ожидание следующего слайда. В «Общих шаблонах викторин» доступны начало, вопрос, результаты и завершение без результатов. Ниже выбирается конкретная викторина: её начало, каждый слайд любого типа и два варианта завершения. Предпросмотр результатов в редакторе показывает сам экран; показывать ли результаты участникам по-прежнему определяет настройка проведения викторины.

Кнопка **«Вернуть к дефолту»** сбрасывает выбранную страницу целиком: фон, добавленные элементы, шрифты и расположение блоков. На отдельном слайде сброс также отключает украшения общего шаблона для этого слайда. Кнопка **«Сбросить всё оформление»** после подтверждения восстанавливает стандартное оформление страниц сайта и всех викторин. Тексты заданий, материалы, ответы, настройки проведения и баллы не меняются. Сброс можно отменить кнопкой «Отменить»; чтобы применить результат, нажмите «Сохранить».

Совместимость старого оформления сохраняется: пока новые экраны отдельно не настроены, ожидание слайда и приглашение используют прежнее оформление ожидания, завершение без результатов — прежнее оформление результатов. Проверки предпросмотра и выбора оформления: `tests/design-pages.js`, запускается в консоли на странице оформления отдельной тестовой установки.

## Обновления через GitHub

Раздел ведущего «Обновления» показывает установленную версию, опубликованный стабильный релиз, изменения и историю установки. Источник по умолчанию — публичный `Zarvad23/quiz-library`; токен GitHub на ноутбуке не нужен. Источник можно изменить только с текущим паролем ведущего. В репозитории хранятся код и проверки; данные мероприятий, пароли, загруженные файлы и резервные копии не публикуются.

Проверка выполняется при открытии раздела, а также раз в минуту при работе ведущего с библиотекой, настройками или монитором, если с последней проверки прошёл час. При закрытом браузере фонового процесса нет. Нет интернета — игра продолжает работать; сведения о новой версии временно недоступны. Установка запускается только кнопкой с подтверждением. Для обновлений нужны расширения PHP `curl`, `zip` и разрешённый `proc_open`; проверки покажут недостающие настройки. Проверка TLS-сертификатов не отключается: при ошибке проверьте время Windows и настройку CA-сертификатов PHP.

Установка скачивает `quiz-library-update.zip` из последнего стабильного GitHub Release, проверяет SHA-256, manifest, список/суммы файлов, совместимость PHP и синтаксис всех PHP-файлов. Содержимое `data` и `uploads` в пакете запрещено. Перед заменой файлов создаётся согласованная копия SQLite и кода в `data/updater/backups`. Все динамические запросы на время замены блокируются общей файловой блокировкой. Во время активной игры установка запрещена, в том числе если игру запустили во время скачивания. После установки отдельный PHP-процесс проверяет запуск и целостность базы. При обычной ошибке восстанавливаются код и база до установки.

Кнопка возврата предыдущей версии восстанавливает **код**, сохраняя текущую базу, включая данные, созданные после обновления. Протокол 1 принимает только версии с совместимым `data_format: 1`: в таких релизах нельзя удалять/переименовывать таблицы или столбцы и менять смысл сохранённых данных. Ломающие миграции должны выпускаться с новым протоколом и отдельной процедурой перехода; они не должны маскироваться обычным обновлением.

При выключении питания, завершении PHP-процесса или иной ошибке вне обработчика сайт остаётся в режиме восстановления. Запустите `recover-updates.cmd` на ноутбуке, затем перезапустите Apache. Скрипт восстанавливает снимок до прерванной установки и не загружает потенциально повреждённый код приложения. Копии не удаляются автоматически; установка проверяет запас свободного места. Изображения и видео не копируются при каждом обновлении, поскольку установщик не изменяет `uploads`; их резервное копирование остаётся отдельной задачей.

Для публикации следующей версии: измените `version.json`, обновите `docs/RELEASE-NOTES.md`, проверьте `python3 tests/run-all.py`, отправьте коммит и тег `vX.Y.Z`. Workflow `.github/workflows/release.yml` запускает проверки на отдельных базах, собирает пакет через `tools/build-release.py` и публикует релиз только после успеха. Обычный push без тега не становится обновлением для ведущих. Не изменяйте опубликованный тег и пакет; исправление выпускайте следующим номером версии.

Локальная сборка пакета: `python3 tools/build-release.py ../quiz-library-update.zip`. Для первой установки механизма один раз скопируйте этот архив поверх прежней платформы по `UPDATE-WINDOWS.txt`. Для новой установки из исходников создайте каталоги `data` и `uploads`, затем выполните `php server/setup.php`.

### Исправление поиска PHP в XAMPP (1.0.2)

В 1.0.1 поиск php.exe мог не находить CLI под Apache, поскольку PHP_BINDIR может содержать путь сборки, а PHP_BINARY — путь сервера. В 1.0.2 сначала проверяется каталог реально загруженного php.ini, затем фактические каталоги PHP/Apache и XAMPP; PATH не используется и не требуется. В дочерний PHP явно передаётся тот же php.ini через `-c`; рабочий каталог соответствует каталогу исполняемого PHP для поддержки относительного `extension_dir`. Кэш проверки привязан к окружению PHP: после включения curl/zip и перезапуска Apache старое сообщение об отсутствующем расширении не сохраняется на час.

Если 1.0.1 не даёт установить исправление автоматически, скачайте `quiz-library-xampp-fix.zip` из релиза 1.0.2, остановите Apache и замените только `server/updater.php` в установленной платформе. Запустите Apache, обновите страницу и нажмите «Проверить обновления». После этого полный выпуск 1.0.2 устанавливается кнопкой. Маленький архив не заменяет version.json и данные, поэтому до полного обновления номер 1.0.1 остаётся прежним.

### Скриншоты к описанию обновления (1.0.3)

После установки 1.0.3 в разделе обновлений рядом с описанием выпуска показывается галерея: миниатюры, подписи и крупный просмотр по нажатию. В просмотре работают кнопки, стрелки клавиатуры и Esc. Если картинка недоступна, описание и установка остаются доступны. Старые выпуски без изображений показываются как прежде. Браузер ведущего загружает картинки с GitHub по мере просмотра; участники их не загружают.

Для публикации положите реальные снимки интерфейса в `docs/release-screenshots/`, имена `screenshot-01-gallery.png`, `screenshot-02-viewer.png` и т. п. В `screenshots.json` укажите список `{ "file": "screenshot-01-gallery.png", "caption": "Описание снимка" }`. Допустимы PNG/JPEG/WebP/GIF, до 8 снимков по 8 МБ. `tools/publish-release.py` проверяет пути/лимиты, прикладывает снимки с подписями к черновику релиза и публикует его после загрузки всех файлов. Если скриншоты не нужны, используйте пустой список или уберите screenshots.json. Сам пакет обновления не содержит скриншоты из документации.

Можно приложить картинки вручную к GitHub Release: используйте те же имена, подпись задаётся полем label вложения. Галерея принимает только картинки из вложений этого публичного репозитория по HTTPS, ограничивает количество/размер и выводит подписи как текст. Произвольный HTML или Markdown из описания не исполняется. Проверка метаданных: `tests/release-screenshots.py`; браузерная проверка на странице обновлений тестовой установки: `tests/release-screenshots.js`.
